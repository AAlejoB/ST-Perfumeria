🧭 Contexto del bug

Qué pasa hoy y por qué.

El admin con [ZAPATO] usa .app-shell { display: grid; grid-template-columns: 240px 1fr } (admin.html:107-118). En ciertos viewports el <main class="admin-main"> aparece debajo del sidebar — no al lado — dejando un espacio negro grande arriba del panel.
Hipótesis técnica: grid item sin min-width: 0 + contenido wide (tablas del Decants, mini-dashboard de Precios & Stock) → el track 1fr no puede shrinkear bajo su contenido → el grid se rompe y el main wrappea a la fila siguiente.
Dispositivo crítico: Samsung Galaxy Tab A9 que usan las empleadas en el local (10-21 ARG). Viewport CSS 1340×800 horizontal o 800×1340 vertical (DPR ~1.5).

El cambio real: 2-3 reglas CSS en admin.html (alrededor línea 266): 
.admin-main {
  padding: 1.2rem 1.4rem;
  overflow-x: hidden;
  min-width: 0;       /* ← fix: permite que el grid item shrinkée */
}
.admin-table-wrap, .stock-stats {
  overflow-x: auto;   /* ← fix: tablas wide no fuerzan el track */
}

✅ Pros

  • Fix preciso de la causa raíz — sin cambiar paradigma de UX
  • Mantiene el [ZAPATO] intacto — cero re-aprendizaje para jefe y empleadas
  • Cambio mínimo de CSS (~5 líneas) — riesgo bajísimo de regresión
  • Sidebar permanente sigue visible en tablet/desktop como hoy
  • Si después hay problema de espacio en Tab A9 vertical, se puede sumar A o B sin tener que rollbackear

❌ Contras

  • Si la tabla es muy ancha, el usuario tiene que scrollear horizontal dentro del wrapper
  • No "libera" más espacio para el panel (sigue siendo ~75% del viewport)
  • El bug es por contenido específico — si mañana metés contenido aún más ancho puede aparecer otro tipo de overflow
